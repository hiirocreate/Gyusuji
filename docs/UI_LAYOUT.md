## 最優先ルール
- 画面構成・画角・操作の流れは、原作（Flash版 Ver0.09）の数値をそのまま再現すること。独自のモダン化・レスポンシブ化・レイアウト変更はしない。
- 迷った場合は「原作でどう見えたか」を優先し、勝手に補完せず質問すること。
- 変えてよいのは、画像素材（同梱のオリジナル素材を使う）と名前、およびこの指示で明示した変更点（チャットの縮小と流れるメッセージ、縦画面、Web版）だけ。

## 1. 画面全体
- 横画面と縦画面の両方に対応する（`docs/SPEC.md` §18の「横向き固定」はこの指示で置き換える）。
- どちらの向きでも、論理キャンバスに描画し、端末画面には縦横比を保ったまま拡大縮小して表示する（余白は黒帯）。端末幅に合わせてUIを流動的に並べ替えない。
- 向きの判定は「画面の横幅 > 縦幅なら横画面」。プレイ中に向きを変えても、ゲーム・通信を中断せずにレイアウトだけ切り替える。

### 1.1 横画面（論理解像度 640×324）
フィールドとステータスは原作と同じ。チャットだけを原作の640×200から、LINEの入力欄程度の高さ44pxのバーに縮小する。

| 領域 | 位置(x,y) | サイズ | 内容 |
|---|---|---|---|
| フィールド | (0,0) | 280×280 | マップ／戦闘画面 |
| ステータス | (280,0) | 360×280 | 4人分の状態ウィンドウ（2×2） |
| チャットバー | (0,280) | 640×44 | 色ボタン＋入力欄＋送信＋ログ（§4） |

### 1.2 縦画面（論理解像度 360×684）
3つの領域を縦に積む。各領域の中身（座標・サイズ・表示内容）は横画面と同じものを使い、領域ごとに位置を移すだけにする。図は `docs/ui_layout_portrait.png`。

| 領域 | 位置(x,y) | サイズ | 内容 |
|---|---|---|---|
| フィールド | (0,0) | 360×360 | 280×280のフィールド（戦闘・各ウィンドウを含む）を丸ごと1.2857倍で表示。表示マス数は7×7のまま変えない |
| ステータス | (0,360) | 360×280 | 横画面のステータス領域をそのまま配置 |
| チャットバー | (0,640) | 360×44 | 横画面と同じ並びで幅だけ詰める（§4） |

- フィールド上のウィンドウ（手番メニュー・アイテム一覧・説明・入手・残り時間など）は、フィールド領域の内部座標のまま描き、フィールドと一緒に拡大する。
- iPhoneの縦長（例 390×844）では上下に黒帯が出るが、黒帯にUIを置かない。
- 画面の向きの判定と切り替えは§1の冒頭のとおり。

## 2. 画角（フィールド）
- 画角は「見下ろし型」（ドラクエ等と同じ見え方）。真上からの俯瞰ではない。
- マス目は画面に平行な正方形グリッド。1マス 40×40px、表示は7×7マス（280×280）。マス目自体はアイソメトリック（菱形）・パース・斜め投影にしない。
- キャラ・敵・NPC・宝箱・山や森などの物は、斜め上（約40°）から見下ろした角度でプリレンダした画像を使う（同梱素材はこの角度で作成済み）。頭頂部と顔・胴体が同時に見える角度。
- それらの画像をマス目の上に置くだけで、カメラの回転・ズーム・角度変更はしない（ゲーム内で3Dカメラを使わない）。
- 画面の下にある物ほど手前に見えるよう、y座標の小さい順に描画する（下の物を後から描く）。
- キャラの描画位置はマス中心から上へ10px（SQU_CHR_OFFS_Y=-10）。足元に楕円の影。
- 手番キャラは他キャラより手前に描く（同じマスに重なったときは手番キャラが上）。
- カメラは手番キャラ（またはイベント対象キャラ）を中心にスクロールする。手番交代やぱるぷん玉で対象が変わるときは画面を切り替える。
- 移動は1マス5フレームの直線補間（24fps基準）。歩き終わるたびにそのマスの矢印方向へ向きを変える。

## 3. ステータス領域（1人分 180×140、2×2配置）
- 背景は黒。手番プレイヤーの枠だけ背景を濃紺（#404080）にして強調する。
- 各ウィンドウ内の配置（ウィンドウ左上基準）：

| 要素 | 位置 | 内容 |
|---|---|---|
| 名前 | 上部 | 6文字まで |
| キャラ画像 | (4,16) | 立ち姿 |
| 歩数 | (124,18) | 3桁 |
| HP/MP | (52,36) | 「H 14 / M 10」の形（各2桁） |
| 所持金 | (106,56) | 3桁＋「G」 |
| アイテム | (10,66) | 32pxアイコン 5列×2段（最大10個） |

- 数字はビットマップ風の数字画像（幅18px）で描く。テキストの流し込みにしない。

## 4. チャット（入力バー＋流れるメッセージ＋会話ログ）
原作の大きなチャット欄はやめ、LINEの入力欄程度の小さなバーにする。メッセージは画面上を流れるように表示する。

### 4.1 チャットバー（高さ44px、画面最下部に常時表示）
左から次の順に並べる（余白6px）。

| 要素 | 横画面 | 縦画面 | 内容 |
|---|---|---|---|
| 色ボタン | 32×32 | 32×32 | タップで文字色を黒→赤→緑→青の順に切り替え。ボタン自体がその色になる |
| 入力欄 | 476×32 | 196×32 | 1行入力。プレースホルダ「メッセージを入力」。最大40文字 |
| 送信ボタン | 56×32 | 56×32 | タップまたはEnterで送信 |
| ログボタン | 56×32 | 56×32 | 送信ボタンの右。会話ログウィンドウを開く（§4.3） |

### 4.2 流れるメッセージ
- 送られたメッセージ（自分・他人・システム）は、ゲーム画面（フィールドとステータスを含む640×280／縦画面は360×640の範囲）の上を右端から左端へ流す。
- 表示形式は「名前: 本文」。文字サイズ16px、白い縁取りの代わりに黒い縁取り（2px）を付け、背景はなし。
- 文字色は送信者が選んだ色。黒は見えにくいため流すときは白で表示する（ログでは黒のまま）。システムメッセージは黄色（#FFE650）。
- 流れる速さは、画面の横幅を約6秒で横切る一定速度（文字列の長さに関係なく同じ速さ）。
- 縦方向に6段（縦画面は10段）のレーンを用意し、空いている一番上のレーンに出す。全レーンが埋まっていたら、先頭が画面に入りきるまで待ってから出す。
- 流れるメッセージは操作を妨げない（タップは下のゲーム画面にそのまま通す）。
- イベントの結果や問いかけ（「宝箱がある。開けますか？」「○○を手に入れた！」「がびょうを踏んづけた！」等）もシステムメッセージとして流す。選択肢そのものは従来どおりフィールド上のウィンドウで出す。
- 設定で「流れるメッセージ：表示する／システムのみ／表示しない」を切り替えられるようにする（既定は表示する）。

### 4.3 会話ログ
- ログボタンで、ゲーム画面の上に会話ログウィンドウ（横画面 560×250 を中央、縦画面 340×520 を中央）を開く。図は `docs/ui_layout_log.png`。
- 中身は、これまでのチャットとシステムメッセージを新しい順に下へ追加した一覧（最大200件）。上下スワイプでスクロールし、開いた時点では最新が見える位置にする。
- 右上の「×」またはログボタンの再タップで閉じる。ログを開いている間もゲームは止めない（手番が来たらログは自動で閉じる）。

## 5. ウィンドウ・メニュー
- ウィンドウは背景色 #203040、白い細枠、角は四角。文字は白。
- メニューはすべて縦並びのテキストリスト。タップで選択（ホバー/フォーカス時は行ハイライト）。ボトムシート・カード型・アイコンボタン化はしない。

| ウィンドウ | 位置 | 内容 |
|---|---|---|
| 手番メニュー | (16,16) | 「移動」「アイテム」 |
| アイテム一覧・ショップ・靴・?ボックス | (16,16) | 32pxアイコン＋名前（＋価格）の縦リスト |
| 説明ウィンドウ | フィールド中央(140,240) | 2行。選択中アイテムの名前と効果 |
| はい/いいえ・分岐 | (16,16) | 2択の縦リスト |
| 入手ウィンドウ | フィールド中央(140,140) | アイコン＋「○○を手に入れた！」／金額 |
| 残り時間 | (140,240)、戦闘中は(140,32) | 30秒経過後に「あと○秒でターン終了」 |
| 結果 | 中央 | 「優勝者は ○○ さんです！」「このウィンドウを閉じるとゲームを終了します」 |

## 6. 戦闘画面（フィールドの280×280内で完結）
- 画面遷移はしない。フィールド領域だけが戦闘表示に切り替わり、ステータス・チャットはそのまま残る。
- エンカウント演出：フィールドの画像を取り込み、60フレームかけて「拡大(1.2→3.0倍)＋回転(6°/フレーム)＋加算合成」で渦巻かせてから戦闘へ。
- 配置：敵 (80,80)、プレイヤー (200,200)、コマンドメニュー (16,200)「たたかう」「アイテム」、敵HP表示 (64,136)。
- 攻撃の流れ：攻撃側が跳ねる(12f)→打撃エフェクト(5f)→ダイス(58f)→ダメージ数字。プレイヤー先攻・交互。逃走コマンドなし。

## 7. ダイス
- ダイスはフィールド上に3D風の画像で転がし、58フレームで止める。複数個のときは位置をずらして並べる（(60,60)、(40,70)、(35,80)の起点から転がす）。
- 合計値の表示は数字画像。いちころは専用ダイス。

## 8. 画面遷移（この順・この形）
タイトル →「一人で遊ぶ／ネット対戦をする」→ 名前入力（6文字まで）→ 部屋選択（8部屋の縦リスト。人数と「ゲーム中」「満員」を表示）→ キャラ選択（5体。HP/MP/運を★で表示）→ 待機（参加者一覧＋「ゲーム開始」ボタン。4人揃うか全員が開始を押すと開始）→ ゲーム → 結果 → タイトル

## 9. 拡張機能のUI
- 仕様書§15〜§18の拡張機能（観戦・スタンプ・早送り・フレンド・ハウスルール等）のUIは、上記の原作画面を崩さない範囲で追加する。
- 置き場所は「チャット領域のボタン」か「既存メニューの項目追加」に限る。新しい常駐HUDやオーバーレイは作らない。
- ハウスルール・フレンド等の設定は、待機画面（ルーム）のメニュー項目として追加する。

## 10. Webアプリ版（iPhoneとのクロスプレイ）
- Android（APK）と同じクライアント（`packages/client`、Vite + Phaser）をWebアプリとしてもビルド・公開する。コードは分岐させず、同じソースから両方を出す。
- 公開先は Cloudflare Pages。ワークフローは同梱の `.github/workflows/web.yml` を使う（Secrets：`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`、`SERVER_URL`）。
- サーバ（Colyseus）は APK版・Web版で共通。どちらの端末からでも同じルームに入れること（クロスプレイ）。
  - 入室時にクライアントのプロトコルバージョンを送り、サーバと一致しない場合は「アプリを更新してください」と表示して入室させない。
  - プレイヤー情報に `platform`（android / ios-web / web）を持たせる（表示はしない。障害調査用）。
  - Web版のサーバURLは `wss://`（TLS必須）。Cloudflare Pages の https から ws:// へは接続できないため。
- PWA対応：`manifest.webmanifest`（名前・アイコン・`display: fullscreen`・`orientation: any`）とService Worker（画像・音の事前キャッシュ）を入れ、iPhoneの「ホーム画面に追加」で全画面起動できるようにする。
- iPhone（Safari）での必須対応：
  - 音は最初のタップで `AudioContext` を再開してから鳴らす（自動再生不可のため）。
  - `viewport` に `viewport-fit=cover, user-scalable=no` を指定し、セーフエリア（ノッチ・ホームバー）は `env(safe-area-inset-*)` で避けてキャンバスを置く。
  - ダブルタップ拡大・ピンチ拡大・引っ張りスクロール（バウンス）を無効化する（`touch-action: none`、`overscroll-behavior: none`）。
  - アプリが裏に回ると通信が切れるため、`visibilitychange` で復帰を検知して自動再接続する（再接続猶予60秒以内なら同じ席に戻る。§17の仕様どおり）。
  - チャット入力時にキーボードが出ても、キャンバスの拡大率は変えない（入力欄だけHTMLの`input`を重ね、`visualViewport`に合わせて位置を調整する）。
- 動作確認：iPhone Safari（縦・横）、Android Chrome（Web版）、Android APK の3つで同じルームに入り、1ゲーム通して遊べることを確認する。

## 11. してはいけないこと
- フィールドを全画面にする、ミニマップを足す、ステータスをHUDとして重ねる
- 戦闘を別シーン・別レイアウトにする
- イベント結果をダイアログやトーストで出す（流れるメッセージとログで伝える）
- チャットバーを高さ44pxより大きくする、常時表示のログ欄を作る
- 真上からの俯瞰画像の使用、アイソメ（菱形マス）、3Dカメラ、ピンチズーム、自由スクロール（観戦機能以外）
- 縦画面用に別のUIデザインを作る（§1.2のとおり領域の位置を移すだけ）
- Web版とAPK版で機能や見た目を分ける

## 12. 進め方
1. まず「タイトル〜部屋選択〜キャラ選択〜1ターン分（移動・イベント1回・戦闘1回）」だけを作る。横画面・縦画面の両方で表示できるようにする。
2. 横画面（640×324）と縦画面（360×684）のスクリーンショットを撮り、`docs/ui_layout_field.png` / `docs/ui_layout_battle.png` / `docs/ui_layout_portrait.png` / `docs/ui_layout_log.png` と上記の座標に1px単位で一致しているか自己チェックする。流れるメッセージは、2人以上で同時に送ったときに重ならないことも確認する。
3. 一致しない箇所を一覧にして報告し、確認を受けてから残りを実装する。
4. 残りの実装後、Web版を Cloudflare Pages に公開し、§10の3環境でのクロスプレイ確認結果を報告する。
